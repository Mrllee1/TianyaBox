# VIP、钻石充值与聊天输入对齐 R6（2026-11-08）

本轮针对用户指出的三个区域：VIP 开通、钻石充值、聊天输入及发送按钮。以原 APK 的布局、资源、适配器和实际导航截图为依据；保持 TianyaBox/main，B 面未改。

## VIP 与钻石充值

- 顶部切换恢复原版选中 16 / 未选中 14 字号、24 间距和 20×4 的 `#00CBFF` 指示条。VIP 使用 `FFF1F4 → FFCEF1 → FFF1F4` 横向背景，充值使用 `F1FDFF`。
- 权益表对照 `fragment_vip.xml` 与 `item_member_power.xml`：标题列 136、表头 40、内容行 38，正式会员列填色与三色边框；勾选/缺省使用原版 `vip_pic_on/off`。
- 套餐与支付区贴底；短空间使用可滚动兜底，不以空白 Spacer 把购买按钮挤出。套餐恢复价格单位、总价、赠钻底栏、选中边框、新人标签和服务端时限倒计时；不会生成随机倒计时。
- 充值恢复 136 高余额块、限时钻石、优先使用提示与明细入口。档位使用原版四张钻石图片，按 `<1000 / <4000 / <20000 / 其余` 切换；150×164 卡片在窄屏缩小，列表独立滚动，支付区保持底部。
- 支付方式使用原版支付宝、微信、推荐和选择资源，展示 `name2/desc/priority`，默认尊重服务端 `checked`。VIP 与充值各自保留套餐和支付方式选择。
- 空目录保持空态和禁用购买；只接受当前目录中的明确套餐 ID、合法价格和支付代码。过期方案提供重新加载；确认时再次检查选择。原有待确认订单持久化、结果未知时不重复创建、回前台查询等流程保留。
- 原版入口取证：`android-vip-r6.png/xml` 和 `android-diamond-r6.png/xml`。旧目录中部分含 diamond 名称的截图实际仍在 VIP 页，本轮以控件树中的选中标题和实际画面重新确认，不沿用文件名推断。

## 聊天输入和发送

- 根因：原实现把黑色 `chat_ico_send` 放在深色输入框中。原 APK 的主题映射实际使用普通主题 `chat_ico_send01`（蓝紫渐变箭头）和暗色主题 `chat_ico_send02`；发送、括号、灵感、更多及快捷项均按原版资源映射修正。
- 空输入显示灵感与更多；有内容显示发送，纯空白不能发送；发送/历史加载中禁用重复提交。增加同步提交状态，防止异步任务尚未开始时重复点按。
- UIKit 输入组件保留中文 marked text 和选择范围，Return 换行。收起键盘最多两行，展开最多四行；展开后显示括号入口，在当前选区插入 `（）` 并将光标放在括号中间，不切断 emoji。
- 输入、更多与灵感面板互斥。灵感请求有独立加载状态；切换面板、开始输入或发送后，旧请求晚返回不能重新打开面板或覆盖当前状态。
- 灵感恢复输入框下方最多三张卡片，左侧填入输入框并聚焦，中间文字按原版直接发送，右侧打开可滚动全文。**测试使用左侧填入和全文入口，没有发送真实建议回复。**
- 保留 R4 的失败草稿恢复；失败不会覆盖等待期间新输入的内容，恢复后光标位于文本末尾。

## 验收边界

本轮不宣称真实开通、充值或聊天计费成功。套餐、价格、促销和支付方式继续以 iOS 接口真实返回为准；布局夹具中的数字不能当作线上报价或权益，也没有复制 Android 会话或更换平台参数以填充目录。

原版聊天仍有 FLAG_SECURE，发送图标和输入布局以 APK 原始资源、XML 和行为代码核对，完整受保护聊天截图逐像素验收未完成。购买按钮的原版 PAG 动画仍使用原生渐变呈现；系统键盘和确认弹层也存在平台差异。

320×568 是预览内的受限视口测试，不是另一台小屏真机。实机安装与账号状态检查不能替代真实消费、所有会员成功态或 B 面客体运行验收。[此前逐页未通过项](../qingqing-parity-20261108/R3.md) 继续保留。
